## 4 问题清单

### BUG-01 · 软删除墓碑丢失（严重 / P0，破坏云同步正确性）

- **位置**：`miniprogram/services/record.service.ts` → `deleteRecord()`（第 75～83 行）；根因在 `utils/storage.ts` 的 `loadRecords()` 第 76～78 行 + `saveRecords()` 第 80～82 行
- **复现步骤**：
  1. 记录 A、B 均存在 → 调用 `deleteRecord(A)`
  2. 存储写入 `[B(active), A(isDeleted:true)]`
  3. 再调用 `deleteRecord(B)` → `loadRecords()` 过滤掉 A → `saveRecords([B(isDeleted:true)])`
  4. 检查 `jj:records` → **A 的墓碑已消失**
- **实际结果**：第二次删除后，先前所有墓碑被永久抹除
- **期望结果**：墓碑保留（`isDeleted:true` + `updatedAtMs`），供阶段 4 同步游标比对
- **判定依据**：方案 §2.5「软删除用 isDeleted 墓碑同步」、§6.2「软删除 + updatedAt，导出保留标记」
- **影响**：阶段 4 开启云同步后，远端仍存在的已删记录会被判为新数据**复活**；本地导出数据也丢失删除痕迹
- **修复建议**：`saveRecords()` 改为合并写回——以入参为活跃集，从磁盘已有全量数据中保留 `isDeleted:true` 的条目后再整体写入；或新增独立的 `markRecordDeleted()` 直接操作全量数组，禁止走 `loadRecords()`

### BUG-02 · requestAnimationFrame 未定义（高 / P1，阻断编译）

- **位置**：`miniprogram/components/number-roller/index.ts` 第 44、47 行
- **报错**：`TS2304: Cannot find name 'requestAnimationFrame'`
- **实际结果**：`tsc --noEmit` 失败；小程序 WebView 逻辑层无全局 rAF，真机运行会 ReferenceError
- **期望结果**：方案 §2.4 要求「requestAnimationFrame 进度驱动」
- **判定依据**：微信小程序逻辑层不提供 window/rAF 全局；`wx.createSelectorQuery` 或 `setTimeout` 才是可用调度原语
- **修复建议**：改用 `setTimeout(tick, 16)`（带 `this._timer` 清理，detached 时 clearTimeout），或统一封装 `utils/raf.ts` 提供 rAF 语义；同步补 `declare` 或避开全局名以通过类型检查

### BUG-03 · getFileInfoSync 不存在（高 / P1，阻断编译）

- **位置**：`miniprogram/utils/image.ts` 第 50 行
- **报错**：`TS2551: Property 'getFileInfoSync' does not exist on type 'FileSystemManager'`
- **实际结果**：`tsc --noEmit` 失败；压缩流程首步取文件大小即异常，被 catch 吞成 `size=0`，导致压缩逻辑空转到第 5 轮直接返回原图
- **期望结果**：单张凭证 ≤200 KB
- **修复建议**：改用 `fs.getFileInfo({ filePath, success })` 的 Promise 包装（在 `wxPromise.ts` 中新增），或 `wx.getStorageInfoSync` 不适用时采用 `statSync`
- **附带风险**：`compressToLimit()` 在 `size===0`（取大小失败）时直接 `resolve(current)` 返回**未压缩原图**，静默违反 200 KB 约束——需改为按路径长度/兜底压缩而非跳过

### BUG-04 · 基础库版本配置冲突（中 / P1，兼容验证失真）

- **位置**：`project.config.json` 第 54 行 `libVersion: "2.30.0"` vs `project.private.config.json` 第 2 行 `libVersion: "3.18.1"`
- **实际结果**：开发者工具以私有配置为准，本地调试全程跑在 3.18.1；方案声明的「最低 2.30.0」从未真实验证
- **期望结果**：验证环境与声明的最低版本一致（或明确用「调试用高版本 + 专项低版本回归」双轨）
- **修复建议**：验收前把 `project.private.config.json` 的 libVersion 调回 2.30.0 跑一轮冒烟，再恢复高版本调试

### BUG-05 · TS 层硬编码色值（低 / P2，规范偏差）

- **位置**：`category.service.ts` 第 17～24、71 行；`stats.service.ts` 第 54 行；`migration.ts` 第 30 行
- **实际结果**：`#8B7BE8`、`#39D0A5` 等色值硬编码在 TS 中，与方案 §5「theme.wxss 为唯一色值来源」字面冲突
- **修复建议**：抽 `utils/tokens.ts` 导出与 theme.wxss 同源的色值常量，或在 WXML 层用 CSS 变量渲染颜色、服务层只返回分类 id

### OBS-01 · Android 全量走实色降级（观察项，需产品确认）

- `utils/compat.ts` `supportsBackdropFilter()` 对 iOS/devtools 返回 true、其余（含全部 Android）返回 false
- 符合方案 R2「精确支持矩阵未确认，保守降级」，但意味着**所有 Android 用户看不到毛玻璃效果**
- 建议：阶段 5 真机走查后按机型白名单放开，勿默认为永久策略

### OBS-02 · 阶段 2 新增模块零单测（风险项）

- 新增 `record.service.ts` / `category.service.ts` / `image.ts` / `keypad.ts` / `number-roller` / `amount-pad` 共 6 个模块，测试文件仍为阶段 1 的 6 个
- 尤其 BUG-01 属于典型「读取-过滤-整体写回」陷阱，若有 `deleteRecord` 连续删除的单测本可提前拦截
- 建议：阶段 2 DoD 补充「新增纯逻辑模块单测覆盖率 ≥ 80%」，并把连续软删除列为必测用例
