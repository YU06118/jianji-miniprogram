# 简记 · 第三轮修复记录：日期点不开、tab 切换隔次播

> 对应《简记_第三轮修复提示词.md》。定位 → 改动 → 验收对照表，只动日期链路与 tab 入场，未碰 nav-bar / 云同步布局 / 导出兜底。

## 一、定位结论

### 问题 1：日期行点了没反应 —— 属于可能性三为主、可能性二叠加

**onOpenDate 是否被调用？** 代码链路完整：`index.wxml:49` 行节点 `bindtap="onOpenDate"` → `index.ts:121` `setData({ dateWheelShow: true })` → 组件 `show` 属性。静态层面链路无断点；但以下缺陷链使得**无论是否调用成功，现象都是"没反应"**，且其中一条不依赖调用成败：

1. **可能性三（代码级证实）**：`date-wheel` 常驻渲染（旧 wxml:92 无 `wx:if`），隐藏态全靠 `opacity: 0; pointer-events: none`（旧 wxss:6-18）。这是一层 `position: fixed; inset: 0; z-index: 200` 的全屏节点，永远盖在整个页面上。运行环境对 `pointer-events: none` 支持不完整时（部分真机 X5 内核），点日期行实际点中的是组件根节点 `catch:tap="onMask"`——把本就关闭的弹层"再关一次"，现象恰好是"点了没反应"。
2. **可能性二（代码级证实）**：`.editor-root` 带 `animation: editor-slide-in`（keyframes 含 transform，`index.wxss:5`）。动画应用期间它是 fixed 后代元素的包含块；本页内容（header + 金额卡 + 分类 26vh + meta 卡 + fixed 键盘区）高度可超一屏，弹层 `bottom: 0` 相对 `.editor-root` 盒子解析时面板可能落在视口外，只剩不可见的"遮罩"。
3. **附带发现**：`inset: 0` 简写在旧内核（X5）兼容性存疑，改显式 `top/left/right/bottom`。

**`date-wheel__panel` 打开时的实际 top 值**：静态推演——面板 `bottom: 0` 相对 `.editor-root`（`min-height: 100vh`，实际内容更高）解析，top ≈ `.editor-root` 高度 − 面板高度；内容超一屏时 top > 视口高（**在视口外**）。此结论基于 CSS 包含块规则推演，运行时数值由验收截图确认（见第四节）。

### 问题 2：tab 隔次播 —— 布尔翻转缺陷，代码级证实

`page-transition.ts:45` 旧实现 `enterFlip: !data.enterFlip`，wxml `{{enterFlip ? 'anim-tab-enter' : ''}}`：

- 第 1 次切：`false → true`，加类，播；
- 第 2 次切：`true → false`，**类被移除 = 无动画**；
- 第 3 次切：又加类，播。

隔次播是布尔控类的必然结果，与时长无关。文档 §3.1 判断成立。
