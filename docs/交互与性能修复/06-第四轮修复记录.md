## 一、定位结论

### 1.1 取证方式

在独立桌面的微信开发者工具（WeChatLib **3.18.1**，与真机走查一致）里，按提示词第七节要求，先在 `exitAndBack` 加两条取证日志：

```
[JJ] exit 2              page-transition.ts:40
[JJ] back 2 true         page-transition.ts:54
```

在「搜索」二级页点返回，控制台打印如上；页面**正常返回首页，未卡灰**。

### 1.2 三条缺陷的判定

| 缺陷 | 提示词描述 | 本机取证结论 |
|---|---|---|
| 一：`===` 身份比较可能为 false，拦掉 navigateBack | 可能 | **未实锤**：本机 `back 2 true`，身份比较为 true，navigateBack 正常发出。但这是"不保证"的隐患，真机/其他版本仍可能触发 |
| 二：定时器与动画同长（200ms），尾帧被切 | 确定 | **代码级确立**：`EXIT_DURATION_MS=200` 与 `--dur-short=200ms` 相同，退栈时动画仍在最后一帧 |
| 三：自绘退出动画与系统右滑叠加 | 确定 | **代码级确立**：`navigateBack` 自带系统右滑，前置 200ms 淡出后系统再滑走一张已透明页，两段动作方向叠加 |

### 1.3 为什么仍选 A 方案

缺陷一未在本机复现，但提示词 2.1 已把 A 方案定为**首选、改动最小、最稳**。关键理由：

1. A 方案不挑根因——删掉自定义退出动画后，缺陷一/二/三**一并消失**（不再有身份比较、不再有定时器、不再有自绘动画与系统叠加）。
2. 用户提供的主桌面截图（分类管理页整体压暗卡住）是真实发生的现象；本机未复现不代表其他环境不会触发，A 方案是从根上消除而非规避。
3. 返回视觉交还系统，与微信原生体验一致，无需维护两套动画时序。

用户截图里"点返回后整页变灰卡住"的现象，与 `pageExiting` 置位后 `.anim-page-exit` 的 `forwards` 把页面钉在 `opacity:0` 完全吻合——只要 navigateBack 因任何原因未发出（身份比较 false、timer 被清、页面实例异常），页面就永久卡灰。A 方案移除这条链路，灰屏从根上不存在。

## 二、改动清单

### 批 1：返回（A 方案）

**`miniprogram/utils/page-transition.ts`**
- `exitAndBack` 重写：删除 `EXIT_DURATION_MS`、`setData({pageExiting:true})`、200ms `setTimeout`、页面身份 `===` 比较；改为重入防护（`_exitRequested`）+ 直接 `wx.navigateBack()`；栈底仍 `reLaunch('/pages/index/index')`。
- 删除 `clearExitTimer` 函数、`TransitionPageLike` 接口、`_exitTimer` 字段；删除 `[JJ] exit` / `[JJ] back` 取证日志（使命完成）。
- `playPageEnter` 调用时机由 `onReady` 改为 `onLoad` 末尾（见批 2）。

**`miniprogram/app.wxss`（转场相关段）**
- 删除 `@keyframes anim-page-exit-kf` 与 `.anim-page-exit`。
- 入场动画收窄：删除根节点 `translateX(12px)`；`@keyframes anim-page-content-enter-kf` 改为 `translateY(8px) + opacity 0→1`，220ms（`--dur-page-enter`）；idle 由 `opacity:0` 改为 `opacity:1; transform:translateY(8px)`（隐藏靠位移不靠透明，慢设备不黑屏）；动画作用到 `.page-content` 后代而非根节点。

**`miniprogram/theme.wxss`**
- 新增 `--dur-page-enter: 220ms`（满足"时长走 token"，不新造裸数值）。

**9 个二级页 wxml 根节点**（about / terms / privacy / category-manage / budget-manage / search / data-manage / record-detail / subpackages/cloud/pages/settings）
- 删除 `{{pageExiting ? 'anim-page-exit' : ''}}` 类绑定。

**9 个二级页 ts**
- 删除 `clearExitTimer` import、`onReady`（只调 `playPageEnter`）、`onUnload`（只调 `clearExitTimer`）。
- `playPageEnter(this)` 移到 `onLoad` 末尾（record-detail 的 notFound 分支不播，可接受）。

**`miniprogram/utils/__tests__/page-transition.test.ts`**
- exit 用例由 6 个精简改写为 4 个：栈底 reLaunch、栈深>1 立即 navigateBack 一次且不 setData、连点重入防护、不比较页面身份（栈顶换引用也照样返回）。删除 `clearExitTimer` 相关 2 例。

### 批 2：tabBar 按压

**`miniprogram/custom-tab-bar/index.wxss`**
- `--hover` / `--pressed` 视觉统一：整项 `transform: scale(0.94)`、文字 `color: var(--color-text-1)`；图标 `transform: scale(0.88)` + `background: var(--color-glass-fill)`（高亮底）+ `border-radius: var(--radius-pill)` + `padding: 2px 10px`。
- 弃用旧的 `translateY(-1px) + opacity 0.85`（深色玻璃底上不可见）；按压不再用 opacity 表达。
- `.tabbar__icon` 过渡加 `background-color`。

**`miniprogram/custom-tab-bar/index.ts`**
- 新增常量 `PRESS_RELEASE_DELAY_MS=180`、`TAB_SWITCH_DELAY_MS=160`。
- `onTouchStart`：连点时重置清按压定时器。
- `onTouchEnd`：**不再立即清**，延迟 180ms 后置 `pressedIndex:-1`（让按压动画走完一帧）。
- `onTouchCancel`：立即清。
- `onTap`：非当前选中项时**延迟 160ms** 再 `wx.switchTab`（先让"按下去"渲染）；切页时间戳也移到延迟回调内写入。
- 新增实例字段 `TabBarInstance`（`_pressReleaseTimer` / `_switchTimer`）+ `ext()` 辅助函数（避免 any），`created` 初始化、`detached` 清理两个定时器。

**`miniprogram/custom-tab-bar/index.wxml`**
- `hover-stay-time` 160 → 300（与 180ms touch 延迟重叠而非互相打断）。

## 五、可复用经验

1. **自定义退出动画要慎用**：`navigateBack` 自带系统右滑，任何前置自绘退出动画都会与系统动画叠加；若自绘动画用 `forwards` 钉住终态，一旦退栈未发出就永久卡灰。最稳的做法是 A 方案——不自定义，交还系统。
2. **身份比较不可靠**：`getCurrentPages()` 每次返回的页面对象引用在开发者工具里不保证同一，`===` 比较可能在某环境为 false 从而拦掉导航逻辑。导航决策应基于"栈深 > 1"而非对象身份。
3. **按压反馈活不到一帧的根因**：`touchstart → setData → touchend(立即清) → tap(同步切页)`，按下态在 60-90ms 内被撤销 + 组件销毁。解法是三段延迟：抬指后 180ms 再清、切页延后 160ms、hover-stay-time 300ms，让按压至少走完一轮动画。
4. **视觉增量要够大**：深色玻璃底上 `translateY(-1px)` + `opacity 0.85` 等于没变；改用 `scale(0.94)` + 图标高亮底 + 文字提亮才肉眼可辨。
