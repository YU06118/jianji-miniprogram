## 二、代码级可复现指标（改前 / 改后）

以下指标不依赖真机，直接由代码结构与调用次数得出，可通过 grep 与单测复现。

| 指标 | 改前 | 改后 | 依据 |
|---|---|---|---|
| 首页 `onShow` 切 tab 时 `queryRecords` 次数 | **2**（全量 + 首页） | **0**（窗口内跳过刷新） | `nav.ts:isRecentTabSwitch` + `index/index.ts:onShow` |
| 首页从编辑页返回时 `queryRecords` 次数 | 2 | **2**（不变，保证新记录可见） | 返回不在 tab 切换窗口内 |
| 统计页 `onShow` 切 tab 时全量聚合次数 | 1 | **0** | `stats/index.ts:onShow` |
| 首页 `refresh()` 的 `queryRecords` 调用 | **2 次** | **1 次**（`all.slice(0, PAGE_SIZE)`） | `index/index.ts:refresh` |
| 上拉分页第 N 页的 `queryRecords` | **2 次**（取第 N 页 + 重取 1..N 全部） | **1 次**（只取第 N 页） | `onReachBottom` 路径 setData |
| 上拉分页 `setData` 载荷 | 整个 `groups` 数组（N 页全量） | 仅 `groups[k]` 或 `groups[k].records` 路径 + 3 个标量 | `patch[`groups[${i}]`]` |
| 首页记录 `wx:key` | `id`（视图字段） | **`_id`（记录主键）** | `index.wxml:54` |
| 图表 canvas `SelectorQuery` 次数 | 每次 `renderChart` **1 次** | 首次 1 次，之后 **0 次**（缓存 `_canvasNode`） | 两个 chart 组件 `renderChart` |
| 图表切月 | 重新查节点 + 重建 | 复用节点，只重绘 | 同上 |
| 图片 `lazy-load` | 0 处 | **2 处**（记账页凭证、详情页图片） | 两处 wxml |
| 图片单张上限 | ≤200KB（已实现） | ≤200KB（不变） | `utils/image.ts:MAX_IMAGE_BYTES` |
| `lazyCodeLoading` | `requiredComponents`（已开） | 不变 | `app.json:42` |
| 单测覆盖 | 162 例 | **166 例**（+4 例 tab 窗口判定） | `nav.test.ts` |

## 三、真机测量方案与目标值（待用户取证）

提示词要求的目标：冷启动首屏 < 1s（1000 条）、tab 切换 < 200ms、记一笔打开 < 150ms、列表滚动 ≥50fps。

### 造数

项目已有造数脚本（见阶段 6 真机走查清单），生成 1000 条记录后重启小程序。

### 测量步骤

| 目标 | 工具与步骤 | 目标值 | 实测（待填） |
|---|---|---|---|
| 冷启动首屏 | 开发者工具「性能」面板，清缓存后重新编译，从启动到首页列表首帧渲染完成 | < 1s | — |
| tab 切换 | 首页 ↔ 统计连切 5 次，取 `wx.getPerformance()` 中 `onShow` 到首帧的时间中位数 | < 200ms | — |
| 记一笔打开 | 点悬浮 + 到抽屉入场动画首帧 | < 150ms | — |
| 列表滚动 | 性能指标里看约 2 秒连续滚动的帧率；1000 条分 50 页 | ≥50fps | — |
| 图表切月 | 统计页连续切月 5 次，看是否出现节点重建（性能面板节点数不增长） | 节点数稳定 | — |

### 取证要求

1. 注明机型、系统版本、微信版本、基础库版本、记录条数。
2. 每项至少 3 次取中位数，附性能面板截图或 `wx.getPerformance()` 原始数值。
3. 若某项未达标，先定位是存储读取、视图渲染还是动画帧，再决定是否继续优化。

## 四、结论（当前可确认部分）

- 本轮在**调用次数与载荷体积**上做了确定性的削减：切 tab 不再全量读、分页不再重取已加载页、canvas 不再重复查询节点。
- 这些改动不依赖真机即可验证（代码级指标 + 166 例门禁全绿）。
- **帧率与耗时目标尚未实测**，本文不编造数值。用户完成上表取证后，把实测值回填即可形成完整对比报告。
