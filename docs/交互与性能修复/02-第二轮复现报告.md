# 交互修复第二轮 · 复现报告

> 依据《简记_交互修复第二轮提示词.md》§六：只定位不改码，等确认。
> 复现手段说明：本环境无真机/GUI 交互能力，采用**代码级定位 + 用户截图与实测现象佐证**；标注【真机确认】的项需真机复核。

## A. 点击日期没反应、滚轮没反应

**看到什么**：`pages/record-editor/index.wxml:52-58`——`<picker class="editor-meta__picker">` 只包住日期值文本，「日期」标签与「今天」按钮都在 picker 热区外；picker 自身无最小热区约束（值区域高约 44px，宽只有右侧一截）。

**实际现象**：点标签无反应 ✓ 成立；滚轮在开发者工具中不响应鼠标滚轮是原生 picker 的工具侧行为，真机只能手指拖 ✓ 成立。

**改法**：弃用原生 picker，新增 `components/date-wheel`（底部弹层 + 年/月/日三列 `scroll-view`，`scroll-with-animation`，`bindscroll` + 160ms 防抖吸附；年月变化重算日列天数——`utils/date.ts` 已有 `daysInMonth/isLeapYear/clampDayToMonth` 纯函数及单测，直接复用；「取消/确定/今天」三操作；遮罩点击关闭不写值）。上限「今天」在逻辑层初始化时算好，不再依赖 `end="{{today}}"`。日期行整体可点（含标签），热区 ≥44px。

**影响**：`record-editor` wxml/ts/wxss + 新组件 `date-wheel`（约 5 个文件）。

## B. 按住 tab 没有按压反馈

**看到什么**：`custom-tab-bar/index.wxml:6`——`hover-class="tabbar__item--hover"` **未设 hover-start-time**（默认约 50ms 才触发）；`index.wxss:49-58` 的按压样式存在但依赖 hover-class。`index.ts:23-31`——`onTap` 第一行 `if (index === selected) return`，点已选中 tab 直接返回。

**实际现象**：快速按下看不到反馈 ✓ 成立（50ms 启动延迟 + 切页后视觉焦点立即转移）；点当前 tab 无任何反馈 ✓ 成立。

**改法**：`hover-start-time="0"`、`hover-stay-time="160"`；再加 `bindtouchstart/touchend/touchcancel` 维护 `pressedIndex`，`pressedIndex === index` 挂 `tabbar__item--pressed` 类（不依赖 hover 平台差异）；指示条在按压项上做 0.9 透明度联动；`onTap` 把按压反馈与切页解耦（已选中 tab 也播按压态）。

**影响**：`custom-tab-bar` 三件套。

## C. 按钮动效只有第一次有效

**看到什么**：`components/glass-button/index.wxml:3`——`hover-class="glass-btn--pressed"` + `hover-stay-time="80"`，**无 hover-start-time**；组件 ts 无任何 pressed 状态，纯依赖 hover-class。`subpackages/cloud/pages/settings/index.wxml:13`——云同步按钮 `variant` 随状态切换（primary↔secondary），class 字符串变化触发重渲染。全项目共 6 处 hover-class（amount-pad、glass-button、glass-cell、nav-bar、tabbar、今天按钮），全部同模式。

**实际现象**：连点第二次起无按压态 ✓ 成立（hover-class 在 setData 重渲染后状态被清除，且无 hover-start-time 时快速点按不触发）。

**改法**：统一改为「显式 pressed 状态」：组件内 `pressed` 字段 + `bindtouchstart/touchend/touchcancel`，按下置 true、抬起延迟 120ms 置 false（定时器可清理，不用 hover-class）；`variant/loading/disabled` 变化不打断按压态；`disabled` 时无按压无闪烁。6 处 hover-class 全部统一（amount-pad 属 budget 页在用，一并改）。nav-bar 返回行为不动（见 E）。

**影响**：`glass-button`、`glass-cell`、`nav-bar`、`custom-tab-bar`、`amount-pad`、`record-editor`（今天按钮）。

## D. 云同步页三张卡叠在一起

**看到什么**：`subpackages/cloud/pages/settings/index.wxml:5-28`——三张 `<glass-card padded>` 直接相邻；`components/glass-card/index.wxss` **零 margin**（grep 0 处）；该页 wxss 也无卡片间距规则。

**实际现象**：用户截图证实——三卡首尾相接，圆角与阴影互相压叠 ✓ 成立。

**改法**：该页内容区加 `.page-stack`（`display:flex; flex-direction:column; gap: var(--sp-3)`，间距走 token）。排查其余多卡页：**data-manage 同病**（wxml 三张卡相邻，wxss 无卡间距）；mine 页卡片间距已有（`.mine-section` margin-top sp-4）；budget-manage 已有（extClass margin-bottom sp-4）；about/terms/privacy 单卡不涉及。统一用同一套 `.page-stack`。

**影响**：`subpackages/cloud/pages/settings` + `pages/data-manage`（其余页确认无需改）。

## E. 返回箭头

**看到什么**：`components/nav-bar/index.wxml:6` hover-class 同 C 模式；行为逻辑（栈底 reLaunch、44×44 热区）在 `utils/page-transition.ts:29-41`，经用户实测可用。

**改法**：**行为零改动**；仅把按压态从 hover-class 换成与 C 统一的显式 pressed（视觉参数不变）。

**影响**：仅 `nav-bar` 样式层。

## F. "只生效一次"隐患清查

逐项代码级核实：

| 项 | 现状 | 结论 |
|---|---|---|
| `.anim-page-push` 常驻类 | 二级页均经 `navigateTo` 打开，**每次新建页面实例**，CSS animation 在首次渲染必播 | 机制上每次都播；但 tab 页实例复用——tab 页未用它（用的是 enterFlip）。**维持现状 + 真机验证**：若真机出现"返回再进不播"，再改进前重置【真机确认】 |
| `.editor-root` 的 `editor-slide-in` | 同上，`navigateTo` 新实例每次播 | 同上【真机确认】 |
| `enterFlip` 时间戳 | `custom-tab-bar/index.ts:27-29`：`lastTabSwitchAt` 在 `wx.switchTab` **之前**写入 ✓ | 无需改 |
| `number-roller` | attached 直接静态文本（无入场动画）；value 变化经 rollTo + generation token 重启 | 切月可重播 ✓ 无需改 |
| `chart-donut` / `chart-bar` | observers 变化即重建 rAF 动画链，切月重播 ✓；但**页面隐藏后 rAF 不停止** | 停止逻辑归属第三批性能项，本轮在图表组件补 `pageLifetimes.hide`/`detached` 取消动画链（小改，随 C 批执行） |
