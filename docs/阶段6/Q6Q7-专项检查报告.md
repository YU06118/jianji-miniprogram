### Q6 衍生缺陷（P2，非 Q6 不符合项）

**BUG-Q6-01 · 退出动画的 setTimeout 在物理返回场景下会多退一层**

- **位置**：`pages/record-editor/index.ts` `closeWithAnimation()` 第 159～165 行
- **逻辑**：`setTimeout(() => wx.navigateBack(), 320)`，但无 timer 清理、无返回拦截
- **风险场景**：用户点关闭/保存后，在 320ms 动画窗口内按物理返回键或左滑返回 → 页面已被系统弹出 → 随后 setTimeout 触发的 `navigateBack()` 在只剩首页的栈上再次执行 → **可能把首页也退掉（回到桌面或前一个非预期页）**
- **判定依据**：`record-editor` 由 `navigateTo` 压栈（栈深=首页+editor）；无 `onUnload` 清理 timer、无 `onBackPress` 拦截；代码层时序推演成立。**属静态推演，真机行为需走查确认**
- **影响**：偶发、边界场景，不阻断 Q6 形态符合性
- **修复建议**：保存 timer id（`this._exitTimer`），在 `onUnload` 中 `clearTimeout`；或加 `onBackPress` 拦截物理返回并复用 `closeWithAnimation`。两者取其一即可

## 6 BUG-Q6-01 修复记录（2026-11-26 00:10，用户「开始 Q8」时顺带处理）

检查报告提出的 P2 缺陷属实（`closeWithAnimation` 的 `setTimeout` 无清理、无返回拦截），已修：

- **`pages/record-editor/index.ts`**：
  - `closeWithAnimation()` 把 timer id 存到 `this._exitTimer`（类型 `ReturnType<typeof setTimeout>`）；
  - 新增 `onUnload()`：页面卸载时 `clearTimeout(this._exitTimer)` 并置 undefined。
- **原理**：无论物理返回键/左滑返回导致页面何时卸载，`onUnload` 必定触发，timer 被清理，杜绝"系统已弹栈后 timer 再 navigateBack 多退一层"。比 `onBackPress` 拦截更简洁可靠。
- **验证**：tsc 0 错误、ESLint 0 错误、`verify:all` EXIT 0（13 套件 123 用例）。
- **状态**：BUG-Q6-01 已闭环；真机 B4 走查时仍可顺带确认退出动画体感，但多退一层风险已消除。
