# 简记 · 阶段 4 · 云同步部署说明

> 云同步是 **P1 可插拔模块，默认关闭**。不部署云开发时，P0 记账、统计、导出导入全部功能不受影响。

## 1 前提条件

- 微信开发者工具中已开通「云开发」，获得环境 ID。
- `project.config.json` 已配置真实 AppID（当前为 `wx7e44ad0c1a857e87`）与 `"cloudfunctionRoot": "cloudfunctions/"`。游客模式 `touristappid` 无法使用云开发；`cloudfunctionRoot` 缺失时开发者工具无法识别云函数目录（阶段 4 检查报告 BUG-01，已修）。
- 云函数 `sync` 已上传部署（见第 4 节）。

## 2 数据库集合

创建 3 个集合：

| 集合 | 用途 | 主要字段 |
|---|---|---|
| `accounts` | 分类（含墓碑） | `_id`、`name`、`type`、`sortOrder`、`builtIn`、`isDeleted`、`updatedAt` |
| `records` | 账单（含墓碑） | `_id`、`accountId`、`type`、`amountInCents`、`date`、`isDeleted`、`updatedAt`、`updatedAtMs` |
| `budgets` | 月度预算 | `_id`、`month`、`accountId`、`amountInCents`、`updatedAt` |

每个集合由云函数自动写入 `_openid` 字段用于隔离。

### 索引建议

| 集合 | 索引 | 用途 |
|---|---|---|
| `accounts` | `_openid` + `isDeleted` | 拉取该用户活跃分类 |
| `records` | `_openid` + `date` | 拉取该用户账单 |
| `records` | `_openid` + `updatedAtMs` | 增量同步排序 |
| `budgets` | `_openid` + `month` | 按月查询预算 |

## 3 权限规则

三个集合均设为「仅创建者可读写」：

```json
{
  "read": "doc._openid == auth.openid",
  "write": "doc._openid == auth.openid"
}
```

> 客户端不直接读写集合，统一通过 `sync` 云函数（服务端用 `OPENID` 上下文隔离），权限规则作为第二道防线。

## 4 部署云函数

1. 微信开发者工具中，右键 `cloudfunctions/sync` → 「上传并部署：云端安装依赖」。
2. 等待部署完成，确认云函数列表中 `sync` 状态正常。
3. 在「我的 → 云同步」开启开关，点击「立即同步」验证。

## 5 同步策略

- **后写为准**：按 `_id` 合并，取 `updatedAt` 较大者。`BillRecord` 优先用 `updatedAtMs`（双字段），`Account`/`Budget` 回退解析 ISO。
- **墓碑同步**：`isDeleted=true` 的记录同样参与合并，较新的墓碑胜出，防止已删记录被远端旧数据复活（阶段 2 修复的墓碑完整性是此策略的前提）。
- **时间相等**：上传方（客户端）优先，保证离线写入不被覆盖。
- **真实增量**：客户端先调云函数 `action='probe'` 拉取远端轻量游标（仅 `_id` + 更新时间），用真实远端算 `pendingUploads`，只上传本地新增/更新记录（含墓碑）。
- **去重与数据安全**：同 `_id` 唯一；云函数用 `doc(_id).set()` upsert 分批写入（每批 20），**不再先删后写**，避免写入中途失败导致数据丢失；墓碑保留不物理删除。
- **失败处理**：客户端同步失败保留本地真源、记录错误到设置，不抛出、不影响记账。

## 6 已知限制

- 云函数每次同步会遍历该用户云端全量做合并（读操作），但写操作只针对合并后的记录 upsert；单次同步仍受云函数时长限制，超大账本（>1000 条）建议真机验证耗时。
- 图片凭证当前仅存本地临时路径，未上传云端；换机后图片需重新添加。列为后续优化项。
- 本说明基于文档与代码实现，真机云环境需在部署后验证。
