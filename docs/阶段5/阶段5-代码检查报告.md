## 4 独立复验（不采信验证报告自述）

### 4.1 generation token 快速切换（阶段 1 就标记的 OBS-3，本次修复）

用可控时钟精确复刻 `number-roller` 的 generation token 逻辑，模拟用户 50ms 内连切 3 次 value（1000→2000→3000 分）：

```
终值 text = 30.00   （期望 30.00）✓
残留 raf 队列 = 0   （期望 0）✓     ← 旧链全部作废，无并发写
最终 gen = 3        （期望 3）✓
```

**结论：修复属实。** 这是前四轮一直没解决的动画竞态，阶段五静态审查主动发现并修掉，动态复验确认终值正确、旧链无残留。

### 4.2 utils/raf.ts 统一

三个组件（number-roller / chart-donut / chart-bar）均改为 `import { raf } from '../../utils/raf'`，本地不再重复定义 `declare const`。✅ 确认无残留的重复定义。

### 4.3 静态脚本 any 检测——发现漏检缺陷

脚本文档注释写"TS 零 any"，但第 68 行判定逻辑：
```js
if (/\bany\b/.test(line) && !/\/\/|\*/.test(line)) anyBad.push(...)
```
即"该行含 `//` 或 `*` 就跳过"。注入测试证明：

| 测试行 | 脚本判定 |
|---|---|
| `const x: any = 1;` | ✅ 检出 |
| `const y = a * b; let z: any = 2;` | ❌ **漏检**（含乘法 `*`） |
| `const n = 3 * 4; const w: any = 5;` | ❌ **漏检** |

当前真实代码未触发（唯一含 `*`+any 的行是 `types/index.d.ts` 的真注释），属**潜在工具缺陷**：未来任何写在乘法表达式同一行的 any 都会漏过。定 P2。

## 5 缺陷与遗留清单

### BUG-01 · 静态脚本 any 检测存在漏检（P2，工具缺陷）

- **位置**：`scripts/verify-static.js` 第 64～70 行
- **问题**：用行内 `/\/\/|\*/` 判断注释，误把含乘法 `*` 的代码行当注释跳过，`any` 漏检
- **影响**：`verify:all` 自称"TS 零 any"却可能漏报，削弱交付门禁可信度
- **修复建议**：改用块注释状态机逐行扫描（跟踪 `/* */` 开关），单行注释只忽略 `//` 之后内容；或直接用 TypeScript 编译器 API / ESLint 的 `no-explicit-any` 规则替代正则（ESLint 已接入，最省事）
