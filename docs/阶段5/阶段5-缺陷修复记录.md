## 2 BUG-01：any 检测漏检

- **独立复现**：我未直接采信报告，先向 `utils/id.ts` 注入 `const leakTest = 3 * 4; let leaked: any = 5;`，跑 `verify-static.js` 仍报 `[PASS] TS 零 any` → 漏检属实，文件已还原。
- **根因**：正则 `if (/\bany\b/.test(line) && !/\/\/|\*/.test(line))` 把乘法 `*` 误判为注释行。
- **修复**：删除自写正则，改用 ESLint CLI 带 `--rule '{"@typescript-eslint/no-explicit-any":"error"}'` 检查（项目已接入该规则，最可靠）。
- **验证**：再次注入同样的 any → `[FAIL] TS 零 any`，并明确报出 `no-explicit-any` 错误；还原后 PASS。

## 4 L2：不按报告建议修改（重要决策）

报告建议把 `pendingUploads` 的 `>=` 改为 `>`，理由是"时间相等的未变更记录仍冗余上传"。

**我做了独立验证，结论是该建议会引入正确性缺陷**：

```
local  = [{_id:'a', note:'本地新版本', updatedAtMs:500}]
remote = [{_id:'a', note:'远端旧版本', updatedAtMs:500}]  // 时间相等但内容不同

>= 上传: ['本地新版本']   ✓
>  上传: []              ✗
```

若改成 `>`：时间相等时客户端不上传 → 云端保留旧版本 → 下次 probe 拿到的远端时间仍相等 → 客户端仍不上传 → **本地版本永远推不到云端，"时间相等本地优先"语义失效**。

- **决策**：保持 `>=`。代价是极罕见的时间相等场景多传一次，正确性优先于这点性能。
- **落实**：`sync-merge.service.ts` 加注释说明理由；`sync-merge.test.ts` 加回归用例锁定。
