## 3 缺陷清单

### BUG-ALL-01 · 跨页同日合并时该日小计未重算（P2，本轮新引入，已复现）

- **位置**：`pages/index/index.ts:162-179` `onReachBottom()` 路径 setData 分支（第 172-175 行）
- **触发条件**：某一天的记录数超过一页（20 条），用户上拉加载第二页，且第二页首条与已加载末组是同一天
- **根因链**：
  1. 第七阶段性能优化把 `onReachBottom` 从「重取全部页 + 整组 `setData({groups})`」改为「只取第 N 页 + 路径 setData」
  2. 跨页同一天时，代码把新增记录并入末组：`const merged = [...groups[lastIndex].records, ...added.shift().records]`
  3. 只写了 `patch[\`groups[${lastIndex}].records\`] = merged`，**未重算 `groups[lastIndex].totalText`**（该日小计）
  4. 小计停留在第一页的旧值
- **复现证据**（一次性测试，已删除）：
  ```
  造 25 条同一天记录（各 100 分）→ 第一页 20 条、第二页 5 条
  合并后记录数 = 25（正确） ✓
  显示小计 = "20.00"，期望 = "25.00"  ❌ FAIL
  对照：改前整组替换做法 = "25.00" ✓
  ```
- **实际结果**：上拉后该日标题小计少算后续页金额，用户看到的日合计与明细对不上
- **期望结果**：合并后小计 = 该日全部记录之和
- **影响**：仅展示层错误，不丢数据、不影响概览卡（概览是全量聚合）、不影响存储与同步。用户可见但对账困惑
- **为何单测没抓到**：`onReachBottom` 是页面方法，依赖 `this.data`/setData，现有 166 例无页面层路径 setData 的覆盖
- **修复建议**（二选一）：
  - A（推荐）：合并时累加小计——`patch[\`groups[${lastIndex}].totalText\`] = formatYuan(parseAmountToCents(groups[lastIndex].totalText) + parseAmountToCents(added[0].totalText))`
  - B：末组不并入，直接让第二页同日记录作为新分组追加（会有重复日期标题，体验略差）
  - 补回归：构造「同日 25 条 + 上拉」断言小计 = 全额
- **判定依据**：性能改动引入的展示回归，非需求变更；改前行为正确、改后错误
