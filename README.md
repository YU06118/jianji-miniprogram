# 简记 · 微信小程序

给家庭记账用的极简小程序。打开就调起系统数字键盘，3 秒记一笔；首页第一眼告诉你**这个月还能花多少**；
快到月底时会提前预警，而不是等超支了才提醒。

**数据全部存在手机本地，不联网、不上传、不需要注册。**

### ② 类目怎么选 —— 这一步最容易踩坑

| 场景 | 建议类目 |
|---|---|
| 个人主体 | **工具 → 记账**（或 工具 → 效率） |

## 三点五、安全设计（和「四」并列，改代码前一起看）

### 1. 外部内容一律过 `utils/safe.js`

**不可信输入** = 用户键盘输入、粘贴的备份文本、剪贴板、以后可能有的接口返回。
处理方式是**白名单重建**——不是"过滤掉坏的"，而是"只挑出认识的字段重新拼一个对象"。
黑名单永远有漏，白名单不会漏。

`store.js` 的每个写入口都已接上：`addRecord` / `updateRecord` / `addGoal` / `updateGoal` /
`saveSettings` / `importJSON`。**新增任何写入口，先在 `safe.js` 里加清洗规则。**

### 2. 所有能被外部撑大的量都有上限

```
备注 30 字 · 目标名 20 字 · 备份文本 2MB · 月数 36 · 单月 2000 笔
合计 20000 笔 · 目标 30 个 · 单目标日志 500 条 · 单笔金额 ≤ 999 万
```

否则一次恶意粘贴就能把本地存储撑爆、把渲染拖死。

### 3. 零网络请求是硬约束

一旦有人加了一行 `wx.request`，这个产品"数据不出本机"的信任凭据就没了。
`tools/security-audit.js` 会拦下来。

## 四、几个关键口径（改代码前先看这里）

### 1. 金额计算一律走「分」
浮点数做金额是经典事故：`0.1 + 0.2 === 0.30000000000000004`。
所以 `store.js` 里所有求和都先 `M.toCents()` 转成整数分，累加后再转回元。
**新增涉及金额汇总的逻辑时，务必照做**，别直接 `amount + amount`。

### 2. 预算预警是「事前」的，不是「事后」的

```
时间进度 = 已过天数 / 当月总天数
花钱进度 = 已花 / 总预算
节奏差   = 花钱进度 - 时间进度        ← 正数表示花得比时间快

预计月底总额 = 日均支出 × 当月总天数
预计超支     = max(0, 预计总额 - 总预算)
```

状态判定：

| 状态 | 触发条件 | 首页表现 |
|---|---|---|
| 正常 | 进度 < 80% 且 节奏差 < 15% | 粉色卡 +「节奏很好」 |
| 提醒 | 进度 ≥ 80% **或** 节奏差 ≥ 15% | 橙色卡 +「按这个速度月底要超」 |
| 超支 | 进度 ≥ 100% | 红色卡 +「已经超支了」 |

关键点是**第二个条件**：即使才花了 40%，如果时间才过了 20%，也会提前提醒。
月底才报警的预警等于骂人。

### 3. 「每天可花」的分母
```
每天可花 = 剩余额度 ÷ 本月剩余天数（含今天）
```
判断剩余天数时含今天，所以 9 月 28 日算「还剩 3 天」（28/29/30）。

### 4. 自动分类是「最长关键词优先」
备注里同时出现 `水果` 和 `水果茶` 时，取更长的关键词所属分类
（否则「水果茶」会被错误归到「买菜」）。规则表在 `utils/categories.js` 的 `KEYWORDS`，
想加词直接往里加即可，**长词自动优先，不用管顺序**。

### 5. 快捷标签怎么学出来的
扫描最近 3 个月的记录，把 `类型 + 分类 + 备注` 相同的归为一组：

- 出现 **≥ 2 次** 才会成为常用标签
- 金额取该组里**出现次数最多的那个**；每次金额都不同时，取**最近一次**用过的金额
- 学到的不足 4 个时，用一组默认标签兜底（早餐 ¥15、买菜 ¥80……）

用户第一次用就有标签可点，用一周后标签逐渐变成他自己的习惯。

## 五、数据存储

按「月」分片存，避免单个 storage key 撑爆微信 1MB 上限：

| key | 内容 |
|---|---|
| `ledger_index_v1` | 有记录的月份列表 |
| `ledger_rec_2026-09` | 该月流水数组 |
| `ledger_settings_v1` | 预算设置 |
| `ledger_goals_v1` | 攒钱目标 |
| `ledger_meta_v1` | 首次使用时间、打开次数 |

容量参考：一条记录约 90 字节，一个月 300 笔 ≈ 27KB，**正常用十年都不会满**。

**注意**：数据存在微信本地缓存里，**卸载小程序、清理微信存储、换手机会丢失**。
所以「我的」页做了备份功能，建议在首次使用后就引导用户备份一次。

## 六、想改成企业版 / 加功能

按价值排序，几个自然延伸方向：

1. **家庭共账**（需求最大）：需要接后端。两个方案——
   - 微信云开发（`wx.cloud`）：改动最小，但按量计费
   - 自建服务：成本可控，但要处理登录态
2. **账期改为「发薪日 → 下个发薪日」**：`date.js` 现在按自然月切，
   加一个 `startDay` 设置即可，改动集中在 `date.js` 和 `store.js`。
3. **截图记账**：调用 OCR（微信有 `wx.serviceMarket.invokeService`），把支付截图自动转成金额。
4. **多人共用一套记账习惯**：把 `KEYWORDS` 抽成可编辑的分类规则，让用户自己训练。

## 七、常见问题

**Q：编译后一片空白？**
A：先确认 AppID 填了（或用了测试号）。再看开发者工具下方是否有报错。

**Q：`wx.getClipboardData` 报错「fail api scope is not declared」？**
A：隐私协议没配。见上面第二节第 ③ 步。

**Q：圆环图不显示？**
A：`canvas type="2d"` 需要基础库 ≥ 2.9.0。开发者工具里把调试基础库调到 3.x 即可。

**Q：想改配色？**
A：全局色板在 `app.wxss` 顶部（`--pink` / `--mint` / `--amber` 等），
分类颜色在 `utils/categories.js` 的每个分类对象里（`color` 主色 + `soft` 淡底）。

**Q：怎么把示例数据换成真实账本？**
A：「我的」→「清空所有数据」→ 开始记你自己的账。

## 八、设计取舍（为什么这么做）

| 决定 | 理由 |
|---|---|
| 打开记账页直接弹键盘，不做「选择记什么」这一步 | 每多一步，放弃率就高一截。记完再分类型是反人性的 |
| 首页第一屏是「本月还能花」而不是「本月已花」 | 已花的钱是沉没成本，看它只会焦虑；还能花的钱才是决策依据 |
| 预警用「按这个速度月底要超 ¥XXX」 | 具体的数字 + 明确的行动，比一个百分比有用 |
| 攒钱进度手动记，不自动从账本扣 | 自动扣会在用户记错账时产生对不上的数，反而增加负担 |
| 不引任何 UI 库、图表库 | 包小、审核快、无网络依赖，也不会因为第三方库停更而挂掉 |
| 提醒文案尽量口语 | 「这个月要悠着点」比「预算使用率已达 82.3%」更容易被看进去 |
